# Учебная платформа --- README

Веб-приложение для управления учебным процессом: пользователями,
группами, курсами, уроками, заданиями, тестами, оценками, посещаемостью
и объявлениями.

## 1. Технологии

-   **Backend:** PHP
-   **База данных:** MySQL
-   **Подключение к БД:** `mysqli`
-   **Frontend:** HTML, CSS, JavaScript
-   **UI-шаблон:** Tabler
-   **Локальная среда разработки:** XAMPP
-   **Редактор кода:** Visual Studio Code
-   **Контроль версий:** Git

## 2. Основные возможности

-   Авторизация и выход из системы.
-   Роли пользователей: Admin, Teacher и Student.
-   Управление пользователями и профилями.
-   Создание учебных групп и назначение преподавателей.
-   Управление курсами, модулями, уроками и учебными материалами.
-   Отслеживание прогресса прохождения курсов.
-   Создание заданий, отправка ответов и проверка работ.
-   Создание тестов, прохождение и автоматический подсчёт результатов.
-   Электронный журнал: посещаемость и оценки по шкале от 1 до 10.
-   Объявления для групп и комментарии к урокам и заданиям.
-   Главная страница со статистикой и меню в зависимости от роли.

## 3. Роли пользователей

  -----------------------------------------------------------------------
  Роль                                Возможности
  ----------------------------------- -----------------------------------
  **Admin**                           Управление пользователями,
                                      группами, курсами и доступом к
                                      разделам системы.

  **Teacher**                         Работа со своими группами, курсами,
                                      уроками, заданиями, тестами,
                                      оценками и посещаемостью.

  **Student**                         Просмотр своих курсов и уроков,
                                      выполнение заданий и тестов,
                                      просмотр оценок и объявлений.

Доступ к страницам должен проверяться на сервере. Скрытие пункта меню
само по себе не является защитой доступа.

## 4. Требования для запуска

Установите:

1.  XAMPP с PHP и MySQL/MariaDB.
2.  Git.
3.  Visual Studio Code или другой редактор.
4.  Современный браузер.

## 5. Установка проекта

### Шаг 1. Клонирование репозитория

Откройте терминал и перейдите в папку `htdocs` XAMPP:

``` bash
cd C:\xampp\htdocs
git clone <URL_РЕПОЗИТОРИЯ> learning-platform
cd learning-platform
```

Замените `<URL_РЕПОЗИТОРИЯ>` на адрес Git-репозитория команды.

### Шаг 2. Создание базы данных

1.  Запустите Apache и MySQL в XAMPP Control Panel.

2.  Откройте <http://localhost/phpmyadmin>.

3.  Создайте базу данных, например `learning_platform`.

4.  Импортируйте SQL-схему проекта:

    `sql/schema.sql`

Если в проекте используется отдельная инструкция или дамп с начальными
данными, следуйте ей.

### Шаг 3. Настройка подключения

1.  Скопируйте `config.example.php` в `config.php`.
2.  Укажите параметры локальной базы данных: хост, имя базы,
    пользователя и пароль.
3.  Не добавляйте `config.php` с реальными паролями в Git.

Пример параметров для стандартной локальной установки XAMPP (если они не
менялись):

``` php
<?php
define('DB_HOST', 'localhost');
define('DB_NAME', 'learning_platform');
define('DB_USER', 'root');
define('DB_PASS', '');
```

Используйте фактические имена настроек, которые ожидает файл подключения
проекта.

### Шаг 4. Запуск

Откройте в браузере:

<http://localhost/learning-platform/>

Если точка входа находится в другом файле или папке, используйте
соответствующий URL.

## 8. Правила разработки команды

1.  Перед началом работы получите последние изменения из `main`:

    ``` bash
    git checkout main
    git pull origin main
    ```

2.  Для своей задачи создайте отдельную ветку:

    ``` bash
    git checkout -b feature/название-задачи
    ```

3.  Делайте небольшие коммиты с понятными сообщениями:

    ``` bash
    git add .
    git commit -m "Добавлена авторизация пользователей"
    ```

4.  Отправьте ветку в удалённый репозиторий:

    ``` bash
    git push -u origin feature/название-задачи
    ```

5.  Создайте Pull Request в `main`. Перед слиянием проверьте изменения и
    разрешите конфликты.

6.  Не изменяйте чужие файлы и общую структуру без согласования с
    командой.

7.  После обновления структуры БД сообщите команде, какие изменения
    нужно импортировать.

## 9. Безопасность и качество

-   Используйте `password_hash()` для сохранения паролей и
    `password_verify()` для проверки.
-   Для SQL-запросов с пользовательскими данными используйте
    подготовленные выражения `mysqli`.
-   Проверяйте авторизацию и роль на каждой защищённой странице.
-   Проверяйте тип, размер и допустимое расширение загружаемых файлов.
-   Не доверяйте имени файла от пользователя; формируйте безопасное имя
    на сервере.
-   Не храните пароли и секреты в репозитории.
-   Экранируйте вывод пользовательского текста, чтобы снизить риск XSS.
-   Проверяйте права доступа к загружаемым файлам.

## 12. План спринта

Работа разделена на семь рабочих дней:

-   **Дни 1--2:** настройка окружения, репозитория, базы данных,
    авторизации и базовых страниц.
-   **Дни 3--5:** реализация основных модулей и интеграция.
-   **День 6:** слияние веток, заполнение тестовыми данными и сквозное
    тестирование.
-   **День 7:** исправление ошибок и подготовка демонстрации.

Сроки и состав задач уточняются командой по мере разработки.

## 13. Вопросы и сообщения об ошибках

Если проект не запускается или обнаружена ошибка:

1.  Проверьте, запущены ли Apache и MySQL.
2.  Проверьте настройки `config.php`.
3.  Убедитесь, что импортирована актуальная `sql/schema.sql`.
4.  Посмотрите сообщение об ошибке PHP и журнал ошибок Apache.
5.  Передайте команде шаги воспроизведения ошибки и текст сообщения,
    удалив из него пароли и другие секреты.
